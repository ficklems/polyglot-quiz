# Quiz project — implementation brief for the coding agent

Extend the existing multilingual quiz application into a polished, replayable demonstration/portfolio project. This is not a commercial game. Inspect the existing repository, framework, UI, data model, and functionality before changing anything. Reuse the existing architecture and visual language; do not rebuild unrelated parts. Preserve existing questions where valid, merge them using semantic deduplication, and keep the original music, history/regional, and general-knowledge content. Do not invent a framework, API, or deployment assumption. Implement the functionality, not a mockup. No monetization, ads, payments, subscriptions, leaderboards, achievements, XP, daily challenges, accounts solely for this feature, social feed, public matchmaking, or extra game modes. Multiplayer can work without accounts.

The attached package contains a 2,807-record draft seed, not 24,400 complete questions. Every record has Ukrainian, Polish and English localizations. The target is 24,400 unique question records; the remaining 21,593 are a generation and verification task, not pre-existing data. Do not claim completion until the actual validated inventory meets that number. Keep the application functional with the available subset and do not display inflated counts. ## 2. UI and catalog

One application, one shared question database. Main menu: (1) Classic Quiz, (2) Multiplayer, (3) Learning Mode, (4) Random Mix, (5) Review Mistakes. Category selection: search, all categories, optionally select several, expand subcategories. Display a second section for Themed Quizzes with all 20 collection cards. No separate database or application for a collection; collections are filtered presets. Make category selection collapsible or paginated if needed; avoid a giant unstructured main screen. Preserve the existing game title unless the owner explicitly requests a rename. Localize every UI label, empty/error state, question, option, answer explanation, accessibility label and collection title in all three languages. Use responsive layouts, keyboard navigation, tap targets, readable text and feedback not conveyed by color alone. Design for desktop and mobile demo recording.

## 3. Languages and region

- Supported locale codes: `uk` (Ukrainian; UI badge UA), `pl` (Polish), `en` (English). Maintain existing locale compatibility (map legacy `ua` to `uk` if needed).
- Language controls presentation; region controls subject matter. A Polish-language question about Ukraine is still regional UA, and a Ukrainian-language question about the USA remains region EN. Every question can be played in any of the three languages.
- Regions: `global`, `UA` (Ukraine), `PL` (Poland), `CE` (Central Europe, e.g. Czechia, Slovakia, Hungary, Austria, with country tags), `EN` (English-speaking countries, primarily USA/UK, also Canada, Ireland, Australia, New Zealand; store country tags). Region is content classification, not a claim about a person's nationality. Global content is not simply English-speaking content.
- Default simple selector: **By language** (uk → UA; pl → PL; en → EN). Prefer ~65% global and ~35% matching regional questions where available. This is a soft sampling target, not a rigid requirement. For region-neutral categories, use global content instead. For explicitly regional subcategories or the Only Locals collection, respect their scope. Allow override to Worldwide (all regions), International only, Ukraine, Poland, Central Europe, English-speaking countries. Explicit regional selection includes global questions by default except strict local presets; show that behavior in the interface. Retain the setting across sessions. Never silently change locale to region or exclude valid translations. When selected region runs out, show a clear smaller pool message and let the player choose Worldwide instead of silently injecting unrelated questions.
- Music: retain 1960s–2010s and add 1950s/2020s; for each decade offer regional and international artists where historically appropriate. History: preserve Ukraine, Poland and Central Europe and add world history and Anglophone history. Geography, food, nostalgia, literature, TV, traditions and sport also benefit from regional questions. Universal STEM questions can be translated rather than recreated.

## 4. Quiz setup and difficulty

Choose one or multiple categories/subcategories, or a thematic collection. Difficulty: Easy, Medium, Hard, Mixed. Difficulty is calibrated to expected knowledge, not question format. Mixed is a session setting, never a question difficulty value. Suggested mixed ratios: 40% easy, 40% medium, 20% hard; use available pool honestly. Choose 10, 20, 30 or 50 questions (default 10 for quick demo), limited by eligible unique IDs. Optional format filter: all accepted formats by default; allow selecting one or more. Do not repeat a question within the same session. Persist recent IDs and prefer unseen IDs across sessions; permit repeats after eligible pool exhaustion and disclose it. Use stable IDs and randomized presentation order for distractors, matching columns and chronology lists. Never use the correct answer's position as the answer key. In multiplayer, use the same questions and same presentation order for all players.

Emoji and text are permitted; maps must be licensed appropriately. Do not implement Guess the Image, Guess the Song, Closest Answer Wins, or Type Your Answer.

Classic scoring: each correctly answered question = 1 point, incorrect or skipped = 0. Ordering/matching use all-or-nothing for initial release, but may show which elements were right in Learning Mode. Display final score, percentage, accuracy by category, and explanations. Ensure answer locking prevents double scoring.

## 6. Approved game modes — exactly five

1. **Classic Quiz** (`classic`): single-player session with configured category, region, difficulty, question count and format filters. Show progress, allow next after answer, final summary, retry with fresh questions and return to menu.
2. **Multiplayer** (`multiplayer`): private room for 2–4 people, display names and room code, host chooses settings, same synchronized question and option order for all, each submits independently; don't reveal correct answer until everyone answers or timer expires. Default 30 s per question, optional host setting, score 1 per correct, ties remain ties. Show round and final score, room empty/full/invalid code handling, reconnect or graceful disconnect handling, no public matchmaking or chat. Reuse existing backend if it supports synchronized state; if none exists, implement a minimal appropriate room service or clearly document a local pass-and-play fallback as fallback, not as online multiplayer. Validate scoring and answers server-side if networked; do not expose correct answer data until round closes.
3. **Learning Mode** (`learning`): untimed, no penalty, immediate correct answer and explanatory feedback, next/repeat and bookmark of mistakes via history. No extra mastery or XP system required. Use contextual explanations, not just repetition of the answer.
4. **Random Mix** (`random_mix`): automatically select across available categories and formats; region/difficulty/count still apply. Balance categories where possible so high-volume music or science does not dominate. Allow start with defaults in one tap.
5. **Review Mistakes** (`review_mistakes`): only questions previously answered incorrectly or explicitly skipped (track both), with current locale and persistent progress. A correct answer marks the item resolved; incorrect keeps it pending. Provide empty state if no mistakes. Reuse IDs, don't duplicate question records; allow retry of missed questions from session results. No account necessary for single-device persistence.

Thematic presets (e.g. Millionaire Challenge with ascending difficulty) are NOT extra game modes. They may preconfigure Classic or other suitable existing modes; no actual money or gambling. Pub Quiz may be played in Multiplayer or Classic. Battle of Generations uses era-balanced content, not inferred ages. The themed quiz names are descriptive placeholders; for public branding, avoid copying official logos or claiming affiliation.

## 8. Data import and model

Use `questions/<category>.json` as canonical source. `questions_seed.jsonl` is an alternative aggregate of those exact records: **do not import both**. `categories.json` includes initial counts, expanded subcategory taxonomy, and target quotas; `collections.json` includes presets. `inventory.csv` is the audit snapshot. Do not mark draft as verified by merely importing it.

Required record fields: `id`, `factKey`, `category`, `subcategory`, `region`, `difficulty`, `type`, `tags`, `localizations` (uk/pl/en), `answer`, `reviewStatus`, `sources`, `verificationNote`. Optional: `countryCodes`, `factDate`, `verifiedAt`, `reviewer`, `geo`, `decade`, `explanationDetails`. For locales: `prompt`, `explanation`, and `options` or `leftItems`/`rightItems`. All option IDs must align in the three locales. For MCQ/TF/year/emoji/higher-lower/location use `answer.correctOptionId`; for order use `answer.orderedOptionIds`; for matching use `answer.pairs` with left/right IDs. Map coordinates reference option IDs. Don't use array index for grading. `sources` holds actual checked URL/citation, publisher, verified date and the fact supported (and license if importing data). Localized explanations should explain why correct, include a date/metric/context where useful. For original mathematical/logic questions, an internal proof/derivation is acceptable. For draft only, source can be missing and explanation basic. `reviewStatus` = draft / verified / published; only verified/published questions are enabled by default in production. For local demo, an explicit `allowDraftQuestions` config may enable drafts, with UI label/notice (no silent production release).
